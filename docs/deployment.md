# Запуск и публикация

## Проверенный локальный запуск

Python 3.12. Создайте venv, установите `requirements.lock.txt`, скопируйте
`.env.example` в `.env`. Для живого AI заполните OPENAI_API_KEY и OPENAI_MODEL.
Без них работает расчёт и явно обозначенный локальный отчёт.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
.\.venv\Scripts\python.exe serve.py
```

Откройте http://127.0.0.1:8520. Не нужно запускать отдельно UI и backend.
На Linux используйте `.venv/bin/python`. Переменные HOST и PORT меняют адрес
прослушивания; по умолчанию только localhost. Старый `run.py` также поддерживается.

## Docker

Dockerfile и compose.yaml подготовлены; сборка контейнера на рабочем компьютере
не проверена, потому что Docker не установлен. Python entrypoint и его API проверены.

```sh
docker compose up --build -d
docker compose logs --tail=50 city
```

Адрес тот же: http://127.0.0.1:8520. Compose читает `.env` во время запуска.
Dockerfile копирует только исходники и зависимости; `.env`, база, git и рабочие
файлы исключены. Том city-data сохраняет рейтинг и дневной счётчик вызовов.
`docker compose down` останавливает приложение и сохраняет том; не добавляйте
`--volumes`, если хотите сохранить результаты команд.

## Публичный Python/Docker-хостинг

Публичный адрес пока не создан: у владельца нет подключённого хостинга.
После создания аккаунта выберите сервис, который поддерживает Python 3.12
или Docker, переменные окружения, HTTPS и постоянный диск.

1. Подключите официальный репозиторий и ветку main. Для приватного репозитория
   может понадобиться разрешение администратора GitHub-организации.
2. Для Python-сервиса: build `pip install -r requirements.lock.txt`, start
   `python serve.py`. Для Docker используйте корневой Dockerfile.
3. Установите HOST=0.0.0.0; PORT берётся из окружения хостинга. В контейнере
   по умолчанию PORT=8080. Health endpoint: `/api/health`.
4. Подключите постоянный диск с правами записи процессу. DATABASE_PATH должен
   указывать на файл на этом диске, например `/data/city.sqlite3`.
5. Добавьте OPENAI_API_KEY и OPENAI_MODEL через защищённые переменные хостинга.
   Ключ не помещают в GitHub, браузер или презентацию.
6. Задайте отдельный DEMO_ACCESS_CODE для жюри и AI_DAILY_LIMIT, например 100.
   Передайте экспертам URL и демо-код; личный аккаунт OpenAI им не нужен.
7. Оставьте один экземпляр приложения. Включите HTTPS средствами хостинга.
   Проверьте сценарий ниже из другого браузера перед передачей ссылки.

Бесплатный эфемерный диск не сохраняет результаты при перезапуске. Приложение
не доверяет X-Forwarded-For: за reverse proxy посетители могут делить лимит IP.
Суточная AI-квота сохраняется в общей SQLite-базе; лимит запросов в минуту и кеш
действуют внутри процесса. Для нескольких экземпляров нужна общая БД и rate limiter.

## Проверка доступа жюри

1. На `/api/health` status=ok. ai_configured означает наличие настроек, а не
   успешный ответ провайдера.
2. Обычный режим → готовый пример → оценка: 56.54307, бюджет 95.
3. AI-анализ: при необходимости введите демо-код. Должно появиться OpenAI и имя
   модели. Резервный отчёт не считается проверкой живого AI.
4. «Найти улучшения» → первая замена: 57.20556 при бюджете 100.
5. Опубликуйте команду, откройте рейтинг в другом браузере и обновите таблицу.
6. Перезапустите сервис и проверьте сохранение рейтинга.
7. Выберите событие: Score изменится, таблица будет отдельной.
