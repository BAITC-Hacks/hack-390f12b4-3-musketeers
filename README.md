# Аким на 5 часов

AI-симулятор управления городом для HackAlem AI / Astana Innovations.
Команда 3-Musketeers.

Выберите пять городских инициатив в пределах 100 условных единиц.
Приложение рассчитает Astana Quality of Life Score, покажет изменения
по районам и объяснит компромиссы. Данные и эффекты синтетические.
Стоимость указана в условных единицах, не в тенге.

## Запуск одним сервером

После установки зависимостей и настройки `.env` выполните `python serve.py`.
Откройте http://127.0.0.1:8520. UI и API работают на одном порту.
`HOST` по умолчанию `127.0.0.1`, `PORT` по умолчанию `8520`.

Docker и публикация: [docs/deployment.md](docs/deployment.md).
Презентация на 8 слайдов: [docs/Akim-Demo.pptx](docs/Akim-Demo.pptx).

## Возможности

- Пять районов, десять показателей, четырнадцать мероприятий из задания.
- Районные и городские эффекты, лаги, синергии и несовместимости.
- Предварительный расчёт черновика и отдельное завершение пяти решений.
- Контроль бюджета и правил в интерфейсе и на сервере.
- Изменения районов, критические значения и точная декомпозиция Score.
- До трёх проверенных улучшений заменой одной меры или её района.
- AI-объяснение через OpenAI Responses API с JSON Schema и ссылками на факты.
- Резервный локальный отчёт при отсутствии ключа или ошибке AI.
- Светлый адаптивный интерфейс с условной интерактивной схемой районов.
- Карточки инициатив с предварительным расчётом до добавления или замены.
- Автосохранение плана и четырёх сценариев сравнения в этом браузере.
- Импорт и экспорт JSON, включая незавершённые планы.

## Быстрый запуск

Требования: Python **3.12**, Git; доступ к PyPI для установки.
После установки расчёт, рекомендации и резервный отчёт работают без интернета.
Проверено на Windows / Python 3.12.14.

Клонируйте репозиторий команды обычным способом через доступный вам GitHub-аккаунт:

```sh
git clone https://github.com/BAITC-Hacks/hack-390f12b4-3-musketeers.git
cd hack-390f12b4-3-musketeers
```

Windows PowerShell:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
.\.venv\Scripts\python.exe run.py
```

Linux / macOS:

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock.txt
.venv/bin/python run.py
```

Если команда `py` отсутствует, используйте полный путь к Python 3.12.
Активация окружения не обязательна: команды выше вызывают его напрямую.

Откройте **http://127.0.0.1:8501**.
Документация API: **http://127.0.0.1:8000/docs**.
`run.py` запускает оба сервиса; Ctrl+C завершает их.
Если порты заняты: `python run.py --api-port 8010 --ui-port 8510`.
Приложение по умолчанию доступно только на локальном компьютере.

`requirements.txt` содержит основные зависимости; `requirements.lock.txt` —
точные версии установленного окружения, включая зависимости для тестов.

## Подключение AI

Скопируйте `.env.example` в `.env` и укажите:

```dotenv
OPENAI_API_KEY=ваш_ключ_локально
OPENAI_MODEL=модель_из_вашего_API_проекта
RULESET=dataset-v1
```

Модель должна поддерживать Responses API и Structured Outputs.
Доступ к модели зависит от API-проекта; подписка на чат не проверяется приложением.
`run.py` читает `.env` при старте. После изменения файла перезапустите приложение.
Переменные, уже заданные в окружении процесса, имеют приоритет.
При раздельном запуске сервисов задайте переменные в их окружении самостоятельно:

```sh
python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
python -m uvicorn frontend.server:app --host 127.0.0.1 --port 8501
```

Интерфейс читает `API_BASE_URL` (по умолчанию `http://127.0.0.1:8000`).
Общий запуск `run.py` устанавливает его по выбранному порту.
API-ключ используется только сервером; `.env` исключён из Git.

Кнопка «Получить AI-анализ» отправляет только рассчитанные факты и проверенные
альтернативы. При успешном вызове показаны провайдер и модель.
Без ключа видна надпись **«Резервный аналитический отчёт»**: это не ответ LLM.
Числа в карточках и подтверждающих фактах всегда поступают из движка.
Сервер проверяет схему, ссылки на факты и идентификаторы рекомендаций;
числа в сгенерированном тексте сверяются с цитируемыми фактами,
а отсутствующие в них числовые значения отклоняются.
Это не полная проверка истинности естественного языка.

### Доступ эксперта

Базовые функции проверяются без персональных аккаунтов и подписок.
Для проверки именно живого AI команда должна запустить сервер со своим
действующим ключом и дать эксперту доступ к демонстрации, либо предоставить
контролируемое тестовое окружение отдельно от репозитория.
Ключи не публикуются в README, JSON или коммитах.
Развёрнутый внешний стенд и демонстрационные доступы в эту версию не входят.
Статус живой проверки фиксируется в [docs/ai-usage.md](docs/ai-usage.md).

## Основной сценарий проверки

1. На «Обзоре города» выберите район на схеме и изучите его проблемы.
2. Нажмите «Готовый пример»: пять мер, расход **95**, остаток **5**.
3. Нажмите «Оценить мой план»: Score **56.54**, прирост **+3.99**, критических значений **0**.
4. Откройте подробные показатели Нуры: школы **48**, медицина **43.75** (интерфейс округляет до одного знака, JSON содержит точные числа).
5. Нажмите «Найти улучшения» и сравните рассчитанные альтернативы.
6. Нажмите «Получить AI-анализ»; проверьте обозначение источника.
7. Задайте название и сохраните результат для сравнения. Примените альтернативу и сохраните второй.
8. Экспортируйте JSON. Его можно загрузить в разделе сравнения;
   сервер повторно проверит правила и пересчитает результат.
9. Попробуйте добавить шестую меру или повтор: интерфейс блокирует действие с причиной.
10. При замене выберите превышение бюджета или конфликт: применение недоступно.

План и до четырёх сценариев хранятся в localStorage браузера и переживают обновление
страницы. При восстановлении сервер заново проверяет сценарии и рассчитывает оценки.
Сохранения привязаны к адресу и порту сайта; очистка данных браузера удалит их.
Для переноса и резервной копии используйте JSON. Это локальное сравнение, не рейтинг команд.

## Правила и формула

Основной набор правил `dataset-v1` следует подробному приложенному датасету:
ровно пять разных мер, максимум две из одного направления, бюджет не выше 100.
Район обязателен для локальной меры; для городской отсутствует или равен null.
Остаток бюджета бонуса не даёт. Порядок мер не важен.

В общем задании перечислены пять направлений, но подробный датасет допускает
отсутствие отдельных направлений и содержит пример с двумя социальными мерами.
До уточнения у постановщика приоритет отдан подробным правилам.
Если подтверждено требование «по одной мере каждого направления», установите
`RULESET=one-per-direction-v1` на сервере. Это дополнительный режим, не объявленное
правило организатора. Сценарии разных правил сервер не смешивает.

```text
I′[d,k] = clip(I[d,k] + Σ(effect[m,k] × (8 − lag[m])/8) + synergy[d,k], 0, 100)
D[d] = Σ(weight[k] × I′[d,k])
D_avg = Σ(populationShare[d] × D[d])
Score = 0.7 × D_avg + 0.3 × min(D[d]) − N_crit
```

`N_crit` — количество значений строго ниже 40. Промежуточные результаты
не округляются. Ограничение 0–100 применяется к показателям после суммы эффектов,
а не к итоговому Score. Стоимость меры оплачивается полностью.
Синергии фиксированные и не уменьшаются лагом.

Контрольные значения:

| Сценарий | Средний балл | Минимум | Критических | Score |
|---|---:|---:|---:|---:|
| Без действий (база сравнения) | 56.8624 | 49.18 | 2 | 52.55768 |
| M7 Нура, M8 Нура, M10 Нура, M12 город, M5 Сарыарка | 58.0776 | 52.9625 | 0 | 56.54307 |

Подробности: [docs/model.md](docs/model.md).

## Архитектура

```text
HTML/CSS/JS → FastAPI UI proxy → FastAPI → validator → deterministic engine
                                    ├── single-replacement search
                                    └── evidence → OpenAI → schema/reference check
                                                        └── local fallback
```

- `data/city_data.json`: версия исходных данных, меры и правила.
- `backend/engine.py`: чистые расчёты, валидация и поиск альтернатив.
- `backend/main.py`: HTTP API, серверный набор правил, лимиты запросов.
- `backend/advisor.py`: LLM, факты, проверка ответа и резервный отчёт.
- `frontend/web/`: интерфейс без сборщика и внешних CDN; SVG-схема, карточки, графики.
- `frontend/server.py`: статические файлы и прокси фиксированных API-маршрутов.
  API-адрес задан на сервере; ключей в браузере нет. Цена и Score всегда приходят из backend.
- `run.py`: запуск двух сервисов одним процессом управления.
- `tests/`: проверки математики, правил и API с подменённым AI-провайдером.

API:

| Метод | Адрес | Назначение |
|---|---|---|
| GET | /api/health | Доступность и наличие AI-конфигурации |
| GET | /api/data | Датасет, база и пример |
| POST | /api/preview | Проверка черновика и предварительный расчёт |
| POST | /api/simulate | Итог только для допустимых пяти решений |
| POST | /api/recommend | Проверенные замены одной меры |
| POST | /api/analyze | Пересчёт на сервере и объяснение |

Тело POST:

```json
{
  "ruleset": "dataset-v1",
  "dataset_version": "dataset-v1",
  "decisions": [
    {"measure_id": "M7", "district_id": "nura"},
    {"measure_id": "M8", "district_id": "nura"},
    {"measure_id": "M10", "district_id": "nura"},
    {"measure_id": "M12", "district_id": null},
    {"measure_id": "M5", "district_id": "saryarka"}
  ]
}
```

Клиентские цены, веса и готовые Score не принимаются. Невалидный набор
возвращает причины отказа без числовой оценки и без вызова AI.

## Ограничения

Синтетические эффекты не подтверждают реальные причинные связи.
Поиск рекомендаций ограничен заменой одного решения и не гарантирует глобальный
оптимум. Общий демо-рейтинг хранится в SQLite; названия команд не удостоверяют личность. AI-кеш и ограничение частоты
действуют в одном процессе: 128 отчётов на 15 минут и 12 запросов анализа в минуту
на адрес клиента. За UI-прокси браузеры делят адрес UI-сервера и его лимит.
Для одного экземпляра есть общий суточный лимит AI в SQLite и необязательный демо-код.
Публичный запуск требует хостинга, HTTPS и постоянного диска; масштабирование
на несколько экземпляров требует общей БД и общего ограничителя частоты. По умолчанию сервисы слушают localhost.

## Городские события и рейтинг команд

В обзоре или каталоге выберите «Суровая зима» либо «Рост нового района».
Это дополнительные учебные режимы: шок применяется к исходным значениям до
реализации мер. Бюджет, каталог и ограничения сохраняются. Прирост считается
от состояния после события. «Обычный сценарий» воспроизводит официальный датасет.
Событие сохраняется в JSON и локальных сценариях; старые JSON работают как обычный режим.

В «Команды» можно опубликовать текущие пять решений. Сервер пересчитывает Score,
хранит последний результат команды и показывает до 50 записей. Сравнение разделено
по ruleset и event_id; версия датасета фиксирована dataset-v1. При равном Score
выше меньшая стоимость, затем сортировка по названию. Токен владельца хранится
только в этом браузере; на сервере — его SHA-256. Это демо, не система удостоверения
участников. Лимит 1000 записей, 12 отправок в минуту на адрес.

База по умолчанию `runtime/city.sqlite3`, путь меняется через `DATABASE_PATH`.
`AI_DAILY_LIMIT=100` ограничивает число новых обращений к провайдеру за день UTC;
неудачные попытки учитываются, попадания в кеш — нет. Счётчик переживает перезапуск.
`DEMO_ACCESS_CODE` при непустом значении защищает AI-анализ: эксперт вводит выданный
код в блоке советника. API-ключ остаётся на сервере. Расчёт и рекомендации доступны
без кода. Не используйте API-ключ как демо-код.

Обоснование правил пяти направлений: [docs/rules-decision.md](docs/rules-decision.md).
